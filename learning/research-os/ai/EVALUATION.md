# Research OS AI evaluation and research

Proposed release and research gates, September 21, 2026. Implementation sequence and data contracts are in [IMPLEMENTATION.md](IMPLEMENTATION.md). No experiment result or product activation is asserted here.

## Dataset and evaluation design

The early accepted-node prototype establishes integration. The release gates here apply after immutable imported-source storage and the structured Quote adapter exist. Use up to 500 permitted paper/claim records to debug ingestion; a smaller subset can support the prototype. The release evaluation uses a frozen corpus with at least 2,000 records across two chosen domains where the founder can judge relevance. Include near-miss results, contradictory sources, terminology changes and questions with no suitable source. Corpus selection rules are set before model comparison; model top hits must not define corpus membership.

The ranking unit is one source document, shown with its highest-ranked passage. Suppress duplicate passages and versions of the same source before the top-five list. Candidate source identity rules are shared by every arm. Source preprocessing, source boundaries and corpus eligibility are shared for model comparisons; each model uses its pinned native tokenizer; report the repaired lexical candidate-recall baseline alongside the current app route so a broken first-token filter cannot manufacture a neural gain.

Use six timed pilot queries and twelve development queries. Compare current lexical search, a corpus-wide BM25 baseline, dense retrieval, and hybrid retrieval plus the proposed reranker on development. Select one neural configuration and the stronger lexical baseline before the sealed run. Tie rules: choose lower observed latency, then the smaller model. The selected configuration and baseline receive the same corpus and per-query candidate budget; report encoder-only and reranker cost apart. Freeze model revisions, scoring settings and the protocol before opening the holdout.

The sealed comparison judges the full union of both top-five lists, at most ten distinct documents, plus two tail/citation candidates selected without knowing the winning system. No evaluated top-five result remains unjudged. If a missing source invalidates a negative control, retain it as an acquisition error and declare the abstention check incomplete until a new protocol is frozen; do not relabel a failed model prediction as a bad query without recorded evidence. Extra candidates help expose missed relevance and enter the common ideal ranking. Within each five-item list, use deterministic source-ID tie breaking. The primary metric is nDCG@5 using the same judged pool and 0-3 topical-utility labels for both arms. Keep zero-relevance cases in a separate abstention cohort; exclude them from the ranking average and report their count. The positive-query power calculation uses only query families with at least one judged usable source. Unexpected all-zero cases in the positive cohort remain in an exclusion log and cannot be replaced after results are viewed; losing enough cases to fall below the planned power yields an inconclusive verdict. Pool recall is a secondary diagnostic with a limited denominator. A claim of corpus-wide recall requires additional judgments.

The user-facing output calls results candidate sources. Freeze separate acceptance thresholds on development for the neural and server BM25 fallback modes before test access; the UI returns an empty accepted-source set when none reaches it, with the text "No source in the reviewed results met the relevance threshold." Evaluate the same thresholded ranking used in the product. The eight negative-control queries must produce zero accepted sources in both modes in the sealed run. Report the observed rate and exact one-sided 95% binomial upper bound, acknowledging the weak bound from eight cases; this is a fixture gate, with no population error-rate claim. The eight cases cannot tune the threshold. A failure blocks promotion and requires a new holdout after changes.

The founder sees randomized candidates and hidden system identity. Topical labels: 0 unrelated, 1 related but unusable for the task, 2 usable with a named limitation, 3 supports the requested task with an identifiable passage. Record method-transfer usefulness as a separate secondary label on development only until its extra annotation cost is measured. Keep machine annotation suggestions out of the founder's primary-label interface. Rejudge a hidden 10% sample after a delay. Reserve disputed cases for adjudication and retain both judgments. These are founder judgments, with no claim of independent expert consensus.

Founder budget: 16 hours for retrieval design and labels, four for task-use checks, four for release and study decisions, and twelve reserved for source-study feasibility and annotations. Let `t` be the pilot's measured median minutes per complete source judgment, with repeats using the same allowance. After pilot/development time is logged, reserve two retrieval hours for disputes and freeze the largest feasible holdout between 24 and 60 queries using `N <= remaining_label_minutes / (12 * 1.1 * t)`, rounded down. Before solving for N, reserve time to construct and judge eight sealed negative-control queries. These ask for an out-of-scope topic or a known withheld source family and receive a corpus-eligibility check plus a complete top-five union review. Use the measured upper-quartile time as a sensitivity case; shrink N before freeze if that case breaches 16 hours. The six pilot queries and twelve development queries never enter the test.

Estimate the query-paired variance on development and simulate power for a 0.10 nDCG@5 effect before test access. This is a planning effect, separate from the release threshold of 0.05. Report the resulting minimum detectable effect and expected power. If fewer than 24 sealed query families fit, or expected power is below 80% for the planning effect, conclude a feasibility pilot and defer the validated quality claim. The founder can still inspect the disabled-by-default local experiment. Adding time or a new corpus starts a revised protocol before outcomes are observed.

Primary estimand: mean paired nDCG@5 difference between the frozen neural configuration and the frozen strongest lexical baseline on the sealed query distribution. Practical release gate: mean improvement at least 0.05 and a query-family paired-bootstrap 95% interval with lower bound above zero, using 10,000 resamples. For the current app baseline, report a separate descriptive comparison. Preserve all query families in one split, including paraphrases; keep source versions and citation-derived rewrites out of opposite splits. Report results by the two chosen domains as descriptive slices. A small slice supports no independent domain claim.

Test one selected configuration once. An interval crossing zero yields an inconclusive quality verdict, with lexical default preserved. After any holdout result is viewed, further model selection requires a new holdout. The evaluation agent holds the manifest and executes the frozen comparison; this is procedural separation inside one AI-assisted team, with no claim of independent scientific validation.

The passage release contract in IMPLEMENTATION, including unmapped source opening and target-bound durable receipts, must pass before the founder workflow gate. A second gate measures the founder's workflow: twelve new tasks split into six matched pairs by domain and difficulty, with arm assignment and order randomized within pairs. Each task asks for two acceptable passages with source locators, within five minutes. The founder cannot repeat the same task under both arms. Judge accepted sources against the frozen task rubric with system identity hidden. Require neural task success on at least five of six tasks, no more than one fewer success than the baseline arm, and median task time no greater than baseline, assigning every failed or abandoned task the full five-minute cap. Report individual outcomes and ordering effects; six tasks per arm support an internal usability decision. They establish no population-level productivity effect. Ranking and workflow gates must both pass for the internal pilot release.

Operational gate: test 200 warm requests at concurrency one, 200 at concurrency two, plus 20 cold starts with a fixed schedule spanning short and long queries and no-answer cases. Include all failures, labeling eight-second timeouts as failures. Record p50/p95/p99, bootstrap uncertainty for warm p95, cold-start range, error rate, peak RSS/VRAM and disk. Proposed limits: warm p95 <=2 seconds at concurrency one and <=5 seconds at concurrency two; cold p95 <=5 seconds; timeout/error rate <=1%. At least 99% of eligible healthy-load requests must execute the selected neural path; record forced worker-down recovery as a separate test. Targets can be revised once after the hardware pilot, before sealing quality evaluation, with reasons recorded. Any revision must preserve the five-minute task requirement.

API limits: query <=512 Unicode code points, 100 fused candidates, 20 rerank pairs, five displayed source documents and an eight-second end-to-end deadline with a six-second worker timeout. Source ID and locator validity must be 100% in fixtures and the held-out output. Run permission/revocation cases for public-to-private transitions, removal, stale caches, unknown source IDs, malformed worker responses and cross-user query caches. Zero unauthorized source disclosures and zero search/inference graph writes are release gates. An explicit Quote action writes verified evidence under the receipt contract in IMPLEMENTATION. Raw query text stays on this host, including telemetry; zero-spend mode prohibits forwarding to external model providers. An opt-in evaluation log expires after 14 days, with explicit local deletion verified at the checkpoint; retain hashes and aggregate metrics for reproduction only when they cannot recover personal text.

## Source-aware research gate

The candidate target is a later independent replication outcome, predicted from the evidence available before that replication's result was public. It has an outcome outside the supplied evidence packet. A four-way support/refute/mixed/insufficient classification from perfect per-passage labels is a Boolean presence task: its oracle requires no learned model and no genealogy. Retain that task only as a pipeline diagnostic. It cannot support a dependency-calibration research claim.

**Target contract.** Select one replication collection and one domain with a common outcome definition. Let `y=1` mean the completed replication meets that collection's prespecified primary replication criterion; `y=0` means a completed eligible replication fails that criterion. A zero is a failed operational criterion, with no inference that an effect can never occur. Missing results, incompatible protocols and incomplete tests are excluded with reason counts before fitting. Preserve the underlying effect estimate and interval for sensitivity analysis. The independent outcome table stays separate from the input corpus.

A candidate collection is the [Social Sciences Replication Project](https://www.nature.com/articles/s41562-018-0399-z), which reports 21 replicated studies and links outcome material. Its records supply an acquisition lead. Genealogy and independent sample size still need inspection. The [Many Labs 2 project repository](https://github.com/ManyLabsOpenScience/ManyLabs2) is another acquisition lead. Verify data terms and outcome conventions before choosing; do not pool unlike success criteria to reach a sample target. Broader collections require the same screening. This is an audit of existing adult research outcomes, with no new learner or human-subject recruitment.

**Four-hour audit.** A research agent retrieves candidate source manifests; the founder reviews up to twelve packets within four total founder hours. Each packet includes: a named original claim/study, eligible pre-cutoff evidence passages and locators, authentic source-family edges, a quarantined later outcome ID and the exact outcome criterion. Stop at four hours or twelve complete packets. At least two fully inspectable examples must show a target outside the evidence inputs, a documented reuse relationship and a separate observation. Require at least four reuse-rich packets and four independent-evidence packets before further sample planning. Record unknown genealogy and all failed acquisitions. These small counts establish acquisition feasibility only.

A reuse edge requires the same underlying study/data identifier or an explicit copied-result trail. Shared authors, methods, wording and citations are features that can help investigate an edge; none alone establishes it. Independence requires a distinct observation or data collection. Ambiguous relationships remain unknown. Confirmed outcomes supply the prediction labels; the founder labels genealogy and input eligibility. Agents can suggest those labels, with review status preserved.

**Leakage contract.** Set each packet's cutoff before its replication result's first public release. Require dated versions for every input and exclude post-result annotations, titles, summaries, citation counts and graph edges. Quarantine the replication paper, its source family and later derivative reports from retrieval and prompts. Split connected components spanning original study, claim family, dataset and reused results as one unit. A component exceeding 20% of eligible packets forces corpus expansion or a narrower feasibility report. Record the excluded share. Mask source names and outcome-linked IDs in learned features; keep provenance in a separate audit table.

The first model uses human-confirmed pre-cutoff stance/quality features and source-family summaries, with no contemporary generative model asked to recall the claim's outcome. Input coders see packets without outcome rows; the evaluation agent holds outcomes for sealed packets. This procedure reduces leakage but cannot erase human familiarity with famous studies. Flag recognized cases, analyze their exclusion, and require later prospective evidence for a strong temporal-generalization claim. Automated extraction is a subsequent experiment with a frozen model and a separate leakage audit.

**Baseline contract.** Every arm predicts the same Bernoulli outcome. Use a constant training base-rate predictor, an original-study-only regularized logistic model, count pooling, exact/semantic deduplication, present HTE component discounting and a compact partial-dependence model. Original-study controls include only fields acquired for the whole chosen collection, such as sample size or original effect precision; prespecify missing-value handling. Counts and HTE projections enter an identical regularized logistic calibration family fitted on training components, keeping their raw scores separate from the predicted replication probability. Validation chooses hyperparameters and the strongest baseline; ties choose fewer fitted parameters then lower runtime. All selection precedes test access.

The candidate adds a bounded number of source-dependence features or learned reuse weights to the same original-study controls. Include a parameter-matched model without genealogy. Exact copies cannot add independent mass. Prediction can still improve or worsen when a separate observation arrives. Preserve the feature list and weight constraints in the preregistration. Training requires enough outcome variation; a constant-class split stops the comparison.

**Statistical contract.** Primary estimand is baseline binary Brier minus candidate binary Brier on natural sealed packets, with equal weight per independent study component. Require observed mean Brier improvement >=0.02 and a component-paired 95% bootstrap lower bound above zero, with 10,000 resamples. On the natural independent-evidence slice, define harm as candidate Brier minus baseline Brier and require its one-sided 95% upper bound <=0.01. Both gates must pass. A candidate that passes the main gate and has an inconclusive guardrail remains unvalidated. Report log loss and duplicate-insertion sensitivity as secondary outcomes.

After the audit and training/development sample, estimate component variance and annotation time. Calculate sample needs for 80% power on both the 0.02 primary difference and the 0.01 preservation margin, with sensitivity to uncertain edges and cluster size. Freeze split proportions, target counts and interval methods before collecting or viewing sealed outcomes. Synthetic variants stay with their parent component and supply no natural-sample power. The small named collections may be insufficient. If the required sample cannot fit the remaining eight founder study hours, accessible records or both outcome classes, end this cycle with a feasibility result. A larger study requires a separate time allocation and new preregistration.

**Mechanism test.** Ablations remove genealogy, shuffle edges, substitute lexical similarity, remove original-study controls and remove partial weighting. A crossed synthetic stress set varies copied/independent records apart from wording overlap, but only natural independent studies can support the primary research claim. Reject the claim if it matches a simpler baseline, fails the preservation gate, depends on known outcome leakage or fails when recognized studies are removed.

**Prior work.** A literature-review agent, separate from the method-authoring role, records searches in Semantic Scholar/OpenAlex or the gateway when available, arXiv and official repositories. Query families cover source copying and truth discovery, dependent evidence fusion, Bayesian evidence models, replication forecasting, study-quality prediction, scientific claim verification and calibration. Record the search date, exact queries, returned IDs and inclusion reasons. Follow backward and forward citations from the closest methods.

Required comparison rows include [copy-aware truth discovery](https://www.vldb.org/pvldb/vol2/vldb09-335.pdf), replication prediction including forecasts reported by the candidate replication collection, SGHA, HypoGeniC and evidence-calibration methods. Record target, data, dependence representation, controls and results. If a prior method matches the candidate contribution, reproduce it or classify the work as adaptation. The founder and critic review this matrix before hypothesis freeze. Without external qualified review, any result remains a preliminary reproducible finding.

Repair runner/writeback scoring parity before baseline measurements. The current acquisition heuristic sums squared uncertainty and omits `GapNode.cost`; cost-optimal acquisition is outside this claim. Replication prediction stays offline even after statistical success. A later product use needs a separate interpretation and transportability evaluation. It cannot become a learner grade, a canon acceptance rule or a generic truth score.

## Education pathway

Teacher preparation is the first education application: finding sources and supporting passages for a concept or assignment. A teacher approves material before it enters a learner-facing lesson. The feature starts with public, age-appropriate corpus selections reviewed for the chosen class level. Accessibility and source-reading burden are part of the workflow check.

K-12 rollout requires an educator partner, age/grade scope, school-approved data handling, relevant consent, a process for correcting errors and human control of assignments. Research involving learners needs review appropriate to the institution and jurisdiction before recruitment. The plan asserts no legal clearance. Ordinary usage data is excluded from model training by default.

Evaluation moves from researcher source-finding, to teacher preparation tasks, to a separately designed classroom study. The classroom primary outcome is delayed transfer on unseen items, with a fixed curriculum and teacher-time measure. Choose randomization unit and power after class availability and pilot variance are known. An underpowered classroom pilot supports feasibility conclusions. It cannot establish reformative education benefits.

Research OS already has an OpenAI-compatible chat seam in `src/lib/research-os/llm.ts` and a default-off `RESEARCH_OS_LLM_ENABLED` flag. HTE uses a separate Claude CLI interface. After the evidence finder passes, a future adult-only extraction increment can use the former to draft typed evidence records with source IDs and exact quote offsets, checked in code and accepted by a person. Its evaluation must measure unsupported fields, omission and review time. It is outside the initial release commitment.

Academy's FSRS, prerequisite credit and existing citation calibration stay unchanged during this program. A later graph-learning proposal needs response-level outcome data and sealed transfer items. Source-citation prediction is a different target from subject mastery.

## Industry news and plan updates

A daily industry watch is part of this program. The scope includes open and commercial models, retrieval systems, typed decision models, scientific agents, multimodal learning, training methods, new evaluation evidence, licenses and operating costs. A closed system may reveal an idea worth testing with open components. Its availability and terms still determine whether its implementation is usable here. Jev and DeepSeek are examples within this broader process.

The existing daily watch runs at 9:00 a.m. America/New_York. It checks primary sources for developments since its last successful run, with a seven-day overlap. It maintains an operator-local news ledger, distinguishes release date from discovery date, and deduplicates by source URL plus model/code revision. A changed result or revision can reopen an assessed item. Save source access failures; do not invent an all-clear when important feeds were unavailable. Notify on material findings or a failure needing action; unchanged conditions stay quiet. The desktop app and machine must be available for local scheduled work.

Triage is bounded to fifteen minutes and up to twelve candidate developments per run, then at most four deep reads. The per-item record contains primary sources, mechanism, evidence level, closest known work, Bucket component, rights/compute constraints, a falsifiable experiment and a disposition. Dispositions: ignore, retain as prior art, evaluate within current scope, or propose a plan amendment. No paid calls or model downloads occur in the watch. A larger investigation is proposed with a budget. This daily check uses the research team; it creates no standing obligation for daily founder review.

A development merits a proposed amendment when it removes a recorded blocker, improves a measured quality/cost tradeoff, invalidates an assumption, or creates a testable research gap. Preserve the frozen benchmark and current release candidate during daily triage. At a milestone boundary, the founder can select one candidate to replace an existing comparison arm; any post-test replacement gets a new holdout. Urgent license or security findings may pause the affected component. Every amendment records its opportunity cost, scope difference and the critic's assessment. An amended architecture must regain a score above 9/10 before its changed commitments are adopted.

## Typed decisions as a release example

TypeSafe's September 15 announcement describes Jev and a training approach named RLCD for typed probabilistic decisions. Its workflow comparisons use other frontier models as reference probabilities. Treat those comparisons as vendor-reported agreement evidence. They establish no Bucket task accuracy. [Announcement](https://typesafe.ai/blog/introducing-system-one-models-and-jev).

The documented interface returns typed choices or scores with probabilities and exposes a truth-valued primitive. Its compositional approach suggests a Bucket component that predicts bounded relevance or routing decisions from a supplied passage. Valid types can still carry incorrect decisions. Probability calibration must be measured against outcomes for the actual task. [TypeSafe documentation](https://docs.typesafe.ai/introduction).

An MIT-licensed comparison adapter supports LLM providers and custom compatible endpoints. That code provides a possible comparison interface; this review established no downloadable Jev weights or right to self-host Jev. Early API access and current terms would need verification before a paid comparison. [Adapter repository](https://github.com/typesafe-ai/system-one-adapter-python).

For Bucket, retain this as an optional replacement for a relevance/abstention comparison arm after the initial feature works. Compare a compact local classifier over frozen embeddings, a constrained local model and an available typed-decision service only if its access and budget are approved. All use the same blinded founder labels, sources and task definition. Measure Brier/log loss, error versus retained coverage, source-ID validity, latency and cost on a fresh holdout. A schema check tests structure; a task label tests the decision. An AI reference label cannot serve as independent ground truth. This pattern could later assist researcher triage and teacher source selection; learner grading remains outside its authority.
