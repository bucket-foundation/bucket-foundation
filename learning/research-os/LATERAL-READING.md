# Research OS for K-12: Lateral Reading on Check

**Status:** shipped, bead `ros-04` addition · **Date:** 2026-09-11 · Reads against `learning/research-os/PLAN-REVISION-3.md` section 2c, `learning/research-os/WORKSPACE.md`, `learning/research-os/PRODUCTION-GUARD.md`, `src/lib/research-os/lateral-reading.ts`, `src/lib/research-os/locate.ts`, `src/lib/research-os/stages.ts`, `src/lib/research-os/production-guard.ts`, `src/lib/research-os/forcing.ts`, `src/app/api/research-os/workspace/route.ts`, and `src/app/research-os/workspace/page.tsx`.

Wineburg and McGrew (2019, `source-evaluation/wineburg-mcgrew-2019-lateral-reading.md`) found professional fact checkers leave the page to check a claim against an independent source before judging it, a strategy the paper names lateral reading, while non-experts stay on one page and are misled by superficial cues. Breakstone and colleagues (2021, `source-evaluation/breakstone-et-al-2021-civic-online-reasoning-national-portrait.md`) measured how far that gap reaches without support: across 3,446 US high school students, 96 percent never learned that a site claiming factual climate reporting had fossil-fuel-industry ties. Check (`grounding.ts`'s `gradeExplanation`) verifies a claim against the node's own summary, one in-workspace source; nothing in that contract corroborated it against an independent second one, the exact step both papers name as the difference between expert evaluation and the failure mode Breakstone and colleagues measured at national scale. This bead closes that gap: a real, independent second source, before a held Check verdict reveals, at the stage where a learner has something of their own to corroborate.

## 1. Locate's "find another source" mode

`src/lib/research-os/locate.ts`'s `findIndependentSources` is Locate's second mode (`POST /api/research-os/workspace` action `"locate"`, `mode: "secondSource"`), given a claim query and the source already quoted (`quotedSourceNodeId`). It runs the same case-insensitive substring filter `locateHits` already uses, never a model call, then excludes the already-quoted node and every candidate whose own provenance is not independent of it, `assessSourceIndependence`'s own comparison: a different publisher AND a different domain, computed against the seed's `provenance.publisher`/`provenance.url` fields. A side with no publisher and no url on file reads independent by default (there is nothing to compare against), with a reason naming the gap rather than a false claim of a real comparison. Results cap at three (`MAX_INDEPENDENT_SOURCES`), each carrying its own `independenceReason` so a learner (or a later reviewer) can see why it qualified. Retrieval only: an adversarial query can narrow or empty the result, never fabricate a candidate or an independence verdict.

## 2. The second-source requirement on Check

`src/lib/research-os/lateral-reading.ts`'s `checkSecondSourceGate` is the pure decision `workspace/route.ts`'s "check" phase 2 (the forcing reveal, `learning/research-os/WORKSPACE.md` section 6) calls on top of `forcing.ts`'s own `finalizeReveal`: revealing a held verdict needs a real, independently-assessed second Quote attached to that same attempt, once the learner's own stage has reached Understanding (`STAGE_ORDER`'s third stage). A learner still at Access or Awareness gets the pre-existing single-source Check contract unchanged, matching the existing forcing gate's own tier-agnostic floor: lateral reading is asked of a learner old enough in this node's own progress to have something to corroborate.

The requirement is a per-class arm switch, the same pattern `forcing.ts`'s `envForcingDefault`/`resolveForcingEnabled` already establish: `RESEARCH_OS_SECOND_SOURCE_REQUIRED` (default on unless exactly `"false"`/`"0"`) and a nullable `graph.classes.second_source_required` override (migration `20260910080000_research_os_lateral_reading.sql`) that wins when set, so a pilot can run a comparison arm's classes on the same deployment as the default-on arm's classes. `db.ts`'s `loadSecondSourceRequiredForLearner` fails open (`null`, deferring to the env default) on any lookup error, so this optional check can never break a Check call, including in an environment where the migration has not run yet.

Three facts gate a reveal, none of them client-reported:

1. `secondSourceNodeId` is present on the reveal request.
2. That node carries a real `"quote"`-kind evidence event for this learner (`db.ts`'s `loadLearnerQuoteEvidence`), never a node id alone with no real Quote call behind it.
3. `locate.ts`'s `assessSourceIndependence`, computed server-side against the two nodes' own provenance, judges the second source independent of the node under Check.

Missing any of the three, the reveal is refused with `SECOND_SOURCE_MISSING_MESSAGE`, a fixed, code-level string ("Find a second, independent source and quote it before you can see your results."), never model output: the tutor's own feedback may NAME that a second source is missing, it never picks or writes one on the learner's behalf. The attempt stays held, exactly the forcing gate's own "there is no separate peek endpoint" floor: a retry on the same `attemptId` with a real second source attached can still succeed. This composes with, never replaces, the forcing gate above it: an incomplete confidence-rating-and-prediction commit still reads as the pre-existing forcing error, the second-source check only runs once that gate has already passed.

## 3. The corroboration evidence event

Once the gate passes, `stages.ts`'s `onCorroborationRecorded` writes a standalone `"corroboration"`-kind evidence event (no stage change, `fromStage === toStage`): the node under Check as `firstSourceId`, the independent node as `secondSourceId`, `locate.ts`'s own `independenceReason` for the pair, and `passagesAgree`, the learner's own mark of whether the two passages say the same thing. `passagesAgree` is never model-judged, the same floor `onCheckResult`'s own `learnerText` already holds for the learner's explanation: the AI never writes the learner's verdict on whether two sources agree. The same "check" event that reveals also carries `secondSourceRequired`/`secondSourceNodeId`, so analysis can group the pilot's data by arm from the evidence log alone, matching `forcingEnabled`'s own purpose.

## 4. The Production guard flag

`production-guard.ts`'s Rule 5, `lateralReadingFlag`, reads every `"corroboration"`-kind evidence event across a learner's whole graph (`db.ts`'s `loadLearnerCorroborationEvidence`) and flags a submitted Production's target node `"single-source"` when no corroboration record names it, from either side, `null` otherwise. Informational only, the same "never blocks submission" posture duplicate detection already carries: `/api/research-os/production`'s POST computes and stores it once, at submit time, alongside `source_provenance` and `duplicate_flag`; nothing here refuses an accept decision the way an unverified source does.

## 5. What this does not do

The gate is scoped to the forcing-held two-phase Check reveal (`WORKSPACE.md` section 6): a learner on an arm with `RESEARCH_OS_FORCING_ENABLED` off gets the pre-forcing immediate reveal, with no natural hold point to attach a second-source gate to, so lateral reading does not apply there. Locate's `"secondSource"` mode scans the whole seeded graph rather than one branch, since an independent second source can sit anywhere; a Phase 0-scale graph makes this an unfiltered table scan, not yet a concern at this seed size. Independence is judged on `provenance.publisher`/`provenance.url` alone, a same-organization mirror hosted on a third domain with no publisher field set would read independent; a stronger provenance model is future work, outside this pass's scope.
