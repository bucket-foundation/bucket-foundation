# Test swarm findings, 2026-09-10

Property-test swarm over the stable `hte` modules (`hte/timeline.py`,
`hte/concepts.py`, `hte/address.py`, `hte/hypothesis.py`, `hte/evidence.py`,
`hte/belief.py`, `hte/unknowns.py`, `hte/export.py`, `hte/periods.py`,
`hte/retrieval.py`, `hte/paper.py`, `hte/referee.py`, `hte/publish.py`,
`hte/pipeline.py`, `hte/llm.py`), run with the `hypothesis` library. Every
finding below is pinned by a `pytest.mark.xfail(strict=True, ...)`
regression test in `tests/swarm/`, so the suite stays green
(`python3 -m pytest -q tests/swarm`) while the defect stays tracked.

**Status (2026-09-10): all six sub-findings resolved.** Every `xfail`
marker listed below has been removed; each regression test now asserts
the fixed behavior directly. See each finding's own **Resolution** note.

## FINDING-2026-09-10-001

- **Module**: `hte/timeline.py`
- **Property**: `relate(a, a) == AllenRelation.EQUAL` for every interval
  (reflexivity), and `converse(relate(a, b)) == relate(b, a)` for every
  pair.
- **Minimal failing input**: `Interval(start=7, end=7)` compared with
  itself (any zero-length interval against an equal zero-length interval).
- **Actual**: `relate` returns `MEETS`, not `EQUAL`.
- **Suspected cause**: `relate`'s branch order checks `a.end == b.start`
  (MEETS) and `b.end == a.start` (MET_BY) before checking `a.start ==
  b.start and a.end == b.end` (EQUAL). For a zero-length interval,
  `a.start == a.end`, so `a.end == b.start` is also true whenever `a` and
  `b` sit at the same point, and the MEETS branch fires first.
- **Fix suggestion**: move the EQUAL check (`a.start == b.start and a.end
  == b.end`) before the MEETS/MET_BY checks, or special-case
  `a.start == a.end == b.start == b.end` to return EQUAL directly.
- **Test**: `tests/swarm/test_timeline_props.py::
  test_relate_zero_length_interval_against_itself_should_be_equal`
- **Resolution**: `relate` now special-cases `a.start == a.end and
  b.start == b.end and a.start == b.start` to `EQUAL` before every other
  check, including the inherited `BEFORE`/`AFTER`/`MEETS`/`MET_BY` order.
  The Lean source (`Bucket.Timeline.relate`) keeps `meets`/`metBy` ahead
  of `equal` too and instead excludes this exact collision from
  `relate_converse_meets_metBy`'s converse proof via its `hnondeg`
  hypothesis, rather than resolving it to `equal`; this fix is a
  narrowly-scoped, documented Python-only divergence from that choice
  (not a Lean edit, and not a reordering of the general branch chain),
  chosen so `relate`'s own reflexivity and converse symmetry hold with no
  exclusion anywhere in the Python API. `test_relate_converse_symmetry_
  holds_for_general_pairs` no longer excludes the collision case, and a
  new `test_relate_of_any_zero_length_interval_against_itself_is_equal`
  generalizes the fixed example across the axis.

## FINDING-2026-09-10-002

- **Module**: `hte/belief.py`
- **Property**: `detectability_scale`'s own docstring claim, "as `delta ->
  0` the ratio approaches 1 and absence stops discriminating."
- **Minimal failing input**: `detectability_scale(1.0, 1e-9)`.
- **Actual**: returns `~1e-9` (approaches 0), not `~1`.
- **Suspected cause**: the docstring describes the intended asymptotic
  behavior of a likelihood ratio (near 1 = uninformative), but the
  implementation (`delta * e_raw_absence`) approaches 0 as `delta -> 0`,
  the opposite limit. The function's actual behavior (weight -> 0) is
  internally consistent with "absence stops discriminating" in the sense
  that the item stops contributing to either side of the pooled weight,
  but the docstring's own stated numeric limit ("approaches 1") does not
  match the formula.
- **Fix suggestion**: fix the docstring to state the formula's real limit
  (approaches 0, meaning the absence item's weight vanishes rather than
  its ratio going neutral), or change the formula to
  `1 - delta * (1 - e_raw_absence)` (or similar) if "approaches 1" was
  the intended contract all along. Flagging for the author to pick a
  side; this repository's own belief-model formulas come straight from
  `main.tex`, so the fix may belong upstream rather than in this package.
- **Test**: `tests/swarm/test_belief_props.py::
  test_detectability_scale_approaches_one_as_delta_approaches_zero_per_docstring`
  (renamed to `test_detectability_scale_matches_the_paper_equation_as_
  delta_approaches_zero`)
- **Resolution**: `main.tex`'s own `eq:detectability`
  (`e_absence = delta * e_raw-absence`) is the formula the implementation
  already carries out exactly; the docstring's claimed `delta -> 0` limit
  of 1 was the side that disagreed with the paper. The existing pinned
  test `tests/test_belief.py::test_detectability_scale_
  limits` already locked in `detectability_scale(0.8, 0.0) ==
  approx(0.0)`. Fixed the docstring to quote `eq:detectability` and state
  its real limit (the ratio, and the absence item's weight, both go to
  0 as `delta -> 0`; `e_absence == e_raw_absence` as `delta -> 1`). No
  change to `detectability_scale`'s arithmetic.

## FINDING-2026-09-10-003

- **Module**: `hte/belief.py`
- **Property**: `fuse` is associative for opinions sharing one base rate.
- **Minimal failing input**: `o1 = o2 = Opinion(b=1.0, d=0.0, u=0.0,
  a=0.0)` (fully dogmatic, agreeing), `o3 = Opinion(b=0.0, d=0.5, u=0.5,
  a=0.0)`. `fuse(fuse(o1, o2), o3) != fuse(o1, fuse(o2, o3))`.
- **Actual**: `fuse(o1, o2)` (both fully dogmatic) collapses to the
  vacuous opinion `(0, 0, 1, a)` regardless of whether `o1` and `o2`
  agree, discarding their shared verdict; folding in `o3` afterward then
  disagrees with folding `o3` into `o2` first (which does NOT hit the
  same zero-denominator branch, since `o2.u=0` but `o3.u=0.5`).
- **Suspected cause**: `fuse`'s zero-denominator guard (`if denom == 0:
  return Opinion(b=0.0, d=0.0, u=1.0, a=o1.a)`) fires whenever `o1.u ==
  o2.u == 0`, with no check for whether the two opinions agree. Two
  agreeing dogmatic opinions (`b=1,d=0` both) should plausibly fuse to
  themselves (`b=1,d=0,u=0`). Full uncertainty is defensible only for the
  disagreeing case (`b=1,d=0` vs `b=0,d=1`), which has no principled
  fused answer of its own.
- **Fix suggestion**: special-case `o1.b == o2.b and o1.d == o2.d` (and
  both `u == 0`) to return `o1` (or `o2`) unchanged, falling back to the
  vacuous opinion only when the two dogmatic opinions disagree.
- **Test**: `tests/swarm/test_belief_props.py::
  test_fuse_of_two_agreeing_dogmatic_opinions_should_preserve_their_verdict`
- **Resolution**: `fuse` now checks `o1.u == 0.0 and o2.u == 0.0` up
  front; when the two dogmatic opinions also agree (`o1.b == o2.b and
  o1.d == o2.d`), it returns that shared verdict unchanged (`u := 0`)
  rather than reaching the zero-denominator branch at all. Two dogmatic
  opinions that disagree still fall back to the vacuous opinion (`u :=
  1`), Jøsang's cumulative fusion having no principled fused answer for
  that case; the docstring now cites Jøsang's own dogmatic-opinion case
  by name. `test_fuse_is_associative_for_a_shared_base_rate` keeps its
  own `u > 1e-9` exclusion, since the disagreeing-dogmatic collapse is
  unfixed by design and still breaks associativity in that one branch.

## FINDING-2026-09-10-004

- **Module**: `hte/belief.py`
- **Property**: the vacuous opinion `(0, 0, 1, a)` is the identity for
  `fuse` under a shared base rate `a`, for every opinion.
- **Minimal failing input**: `o = Opinion(b=0.0, d=2.220446049250313e-16,
  u=0.9999999999999998, a=0.75)` fused with `vacuous = Opinion(b=0.0,
  d=0.0, u=1.0, a=0.75)`.
- **Actual**: `fused.b`, `fused.d`, `fused.u` all come out correct
  (matching `o`), but `fused.a == 1.0`, not `0.75`.
- **Suspected cause**: the combined-base-rate formula divides by
  `a_denom = u1 + u2 - 2*u1*u2`, guarded against division by zero only
  when `a_denom == 0` exactly. When `u1` is a handful of floating-point
  ULPs below `1.0` (a realistic value: `Opinion.from_evidence` produces
  exactly this shape whenever pooled evidence weight is enormous relative
  to `W`) and `u2 == 1.0`, `a_denom` is a few ULPs above zero rather than
  exactly zero, so the division runs anyway and catastrophically amplifies
  the rounding error already present in `u1`.
- **Fix suggestion**: widen the zero-denominator guard to a small
  epsilon (e.g. `abs(a_denom) < 1e-9`) rather than exact equality, falling
  back to the same `(o1.a + o2.a) / 2` branch in that near-degenerate
  window.
- **Test**: `tests/swarm/test_belief_props.py::
  test_fuse_vacuous_identity_is_numerically_unstable_just_below_u_equals_one`
  (renamed to `test_fuse_vacuous_identity_holds_just_below_u_equals_one`)
- **Resolution**: the `a_denom == 0` guard is now `abs(a_denom) <
  1e-9`. Inside that window, the combined base rate falls back to the
  mean of `o1.a`/`o2.a` weighted by each opinion's own confidence `1 -
  u` (an opinion at `u == 1` carries no information about its base rate
  and is weighted out), rather than a plain unweighted average; when
  both weights are zero too (`u1 = u2 = 1` exactly, the one case this
  window still reaches at the boundary), that reduces to the same plain
  average the old exact-zero branch already used, so `fuse(vacuous,
  vacuous)` is unaffected. `test_fuse_has_the_vacuous_opinion_as_
  identity`'s own `1e-6` exclusion band comfortably covers the new
  `1e-9` epsilon, so it needed no change.

## FINDING-2026-09-10-005

- **Module**: `hte/pipeline.py`
- **Property**: `run_pipeline`'s per-stage skip reason accurately
  describes why a stage was skipped, and its overall `"outcome"` reflects
  whether anything useful happened.
- **Minimal failing input**: `run_pipeline({"from_run":
  "/tmp/does-not-exist-abc123"})` (any `from_run` naming a directory with
  no `MANIFEST.json`).
- **Actual** (two sub-findings, one root cause):
  - **005a**: `emit_paper`/`referee`/`publish`'s own skip reason is the
    hardcoded string `"no usable run directory: from_run was not given
    and run_campaign did not produce one"`, printed even though
    `from_run` WAS given, just pointing at an invalid path. A caller
    debugging a typo'd `--from-run` reads a message that flatly denies
    they passed the flag.
  - **005b**: the top-level `"outcome"` field reads `"ok"`, not
    `"failed"`, even though every stage was skipped and nothing ran: each
    `_skipped_stage` call sets `ok=True` by design (a deliberate skip is
    not a failure), so `all(s.ok for s in stages.values())` is vacuously
    true when every stage skips, indistinguishable from a pipeline that
    legitimately had nothing to do.
- **Suspected cause**: the hardcoded reason string in `run_pipeline` (the
  `reason = "no usable run directory: ..."` line) does not branch on
  whether `cfg["from_run"]` was set at all; and `_skipped_stage`'s own
  `ok=True` convention, correct for an intentional skip (a period this
  package has no corpus loader for, say), gets reused for the "nothing
  in this pipeline ran at all" case with no distinguishing signal.
- **Fix suggestion**: interpolate the actual `cfg["from_run"]` value (or
  its absence) into the reason string; and either add a distinct
  `"outcome"` value (e.g. `"skipped"`) for the case where every stage
  skipped, or have `run_pipeline` itself treat "`from_run` given but
  unusable" as a hard failure rather than a stage skip.
- **Tests**: `tests/swarm/test_pipeline_props.py::
  test_missing_from_run_skip_reason_should_mention_the_path_that_was_given`
  (renamed to `test_missing_from_run_error_reason_should_mention_the_
  path_that_was_given`),
  `tests/swarm/test_pipeline_props.py::
  test_missing_from_run_outcome_should_not_read_ok`
  (renamed to `test_missing_from_run_outcome_should_read_error_not_ok`)
- **Resolution**: `run_pipeline` now validates `from_run` up front into a
  `from_run_error` string naming the actual path and precisely which way
  it failed (missing/not-a-directory vs. present but no `MANIFEST.json`).
  When set, `emit_paper` runs through a new `_failed_stage` helper
  (`ran=False, ok=False, error=from_run_error`, still writing its own
  `STAGE.json`) instead of `_skipped_stage`'s `ok=True` convention, and
  `referee`/`publish` cascade-skip off that failure the same way they
  already did for a real `emit_paper` exception. The non-`from_run` "no
  usable run directory" path (`run_campaign` legitimately produced
  nothing) is unchanged and still reads as a deliberate skip, since that
  case's own failure, if any, already surfaces through `run_campaign`'s
  own `ok`. The top-level `outcome` field gained a third value, `"error"`
  (bad input, distinct from `"failed"`, a stage that ran and raised),
  which fires whenever `from_run_error` is set; `"ok"` is no longer
  reachable through that path.
  **Cross-file follow-up (outside this fix's file scope):**
  `tests/test_pipeline.py::test_missing_manifest_in_from_run_skips_
  downstream_stages` pinned the exact bug this finding describes
  (`assert summary["outcome"] == "ok"  # every stage reports ok=True,
  just not run`); its two `"ok"` assertions were updated to `"error"` to
  match, since leaving them would fail the full suite against the
  corrected behavior this finding requires. No other assertion in that
  file changed.
