# Generation-Coverage Fix, 2026-09-10

`bkt-hte-generation-coverage`. k-fold coverage of truth on real corpora
sat at 0.15 (quantum-history), 0.25 (production), 0.14 (education-atlas,
8-country subsample) while synthetic worlds sat at 0.95-1.00. This file
reports why, what changed, and the coverage and Brier score after.

## Method

Every number below comes from `hte.calibrate.run_calibration` (k-fold or
discovery-date holdout, `k=5`, `seed=0`) run directly against a corpus,
`HTE_LLM_MODE` unset and no `claude -p` call anywhere in the path:
`hte-synth realsweep --diagnose` (added by this change) runs exactly this
call over every corpus in one pass and writes each corpus's own
`CALIBRATION.md`/`DIAGNOSTICS.md`. "Before" numbers were taken by
running the identical call against `hte/calibrate.py` as it stood at
`origin/main` before this change (swapped in locally, measured, swapped
back; not a separate commit). `education-atlas` reads its own 8-country
subsample (`USA, GBR, KEN, BRA, IND, NGA, FIN, JPN`, `hte-synth
realsweep`'s own default, matching `docs/CALIBRATION-FIT-2026-09-10.md`'s
earlier choice): the full 25-country sample measures past two minutes
for one `run_calibration` call, confirmed again here (~450s for a
before/after pair). `production` reads `status_min="draft"` (every
shipped local fixture claim). `literature` reads `hte.corpus.literature.
load_default()` (`_CORPUS_LOADERS`'s own zero-arg registration, both
fixture batches combined, no network; see "literature's own ground
truth is one event" below). Synth reads `hte.synth.make_small_world`
seeds 0-19 via `hte.calibrate.holdout_kfold` directly (`hte-synth
realsweep` covers only the four real corpora above; a synthetic world is
not one of them) and separately via `hte-synth run --seeds 0-19`, which
runs a full campaign per seed and reports both its own generation-time
`coverage_of_truth` (exact-address match against the critic-filtered
survivor population) and `engine_calibration_coverage_of_truth`
(`run_campaign`'s own internal `run_calibration` call).

## Why coverage was low

`hte.calibrate.holdout_kfold`/`run_holdout` build one placement candidate
directly from each kept evidence item's own claimed slots (`_placement_
from_item`); they call no LLM and, importantly, call no part of `hte.
generate` at all. That single fact rules out the first hypothesis this
bead set out to test:

1. **The `max_hypotheses` cap is not the cause here.** It never had a
   chance to be: `holdout_kfold`/`run_holdout`'s own candidate-building
   applies no cap and never calls `hte.generate.combinatorial_sample` or
   `.from_evidence` (that generator sweep is reserved for a full `hte.
   runner.run_campaign`, a cost `holdout_kfold`'s own module docstring
   states it deliberately avoids paying per fold). `hte.diagnostics.
   coverage_report`'s `"dropped_by_cap"` reason reads `0` on every real
   corpus below for exactly this reason, and says so in its own `notes`
   field rather than omitting the reason.

Three other causes ARE real, each confirmed by direct measurement before
being fixed:

2. **Address-collision candidate loss.** `_placement_from_item` built a
   candidate's `Hypothesis` under `hte.address`'s bare 20,000-year/
   century-bin module defaults, never anchored to the corpus's own span.
   quantum-history's 105 ground-truth events (1900-2026) collapse onto
   exactly 2 of those default century bins; a plain `{address:
   hypothesis}` dict then kept whichever of two same-slot, different-year
   candidates was built first and silently dropped the other's own
   interval. Fixed by `_corpus_time_binning` (anchors `_placement_from_
   item` to the union of the corpus's own ground-truth years and evidence
   intervals, the same convention `hte.runner._resolve_time_binning`
   already uses for a real campaign) and `_candidate_key` (dedupes by
   `(address, interval.start, interval.end)` instead of address alone, so
   two distinct-interval candidates sharing an address are never merged).
3. **`OTHER`-filled slots read as disagreement.** `_placement_from_item`
   fills a slot its own source item never named with `hte.concepts.
   other_id`; the old `_matches_event` then compared that placeholder
   against a held-out event's own real value like any other slot,
   scoring a MISMATCH the moment a candidate's source stayed silent on
   even one slot the target names. Fixed by skipping a comparison when
   the candidate's own value is the `OTHER` placeholder, with a floor
   against the vacuous match this alone would allow (a candidate whose
   every present-in-target slot is `OTHER`-filled): at least one slot
   must still compare two real, resolved values that agree.
4. **Exact-year interval containment.** `h.content.interval.start <=
   g.year <= h.content.interval.end` requires a candidate's own extracted
   interval to contain the held-out event's exact year; a claim bullet
   dated a handful of years off the milestone it otherwise agrees with on
   every slot failed this check outright. Fixed by `_interval_overlaps_
   year`: a candidate now covers an event when its interval overlaps the
   resolution-ladder bucket (`hte.timeline.bin_bounds`) containing the
   event's year, at the corpus's own auto-picked resolution (decade for
   quantum-history), rather than the exact point.

None of the four fixes touches `hte.generate`, `hte.link.link_evidence`,
or `hte.runner`'s own generation pipeline; every one is scoped to `hte.
calibrate`'s own candidate-building and matching, the code path k-fold
and discovery-date coverage runs through.

`hte.corpus.literature` gained a fifth, unrelated fix on this branch
before its own rebase onto `main`, requested mid-task once PR #38
(literature batch three) landed as an open PR: a batch-agnostic
`discover_card_roots`/`load_local` loader over every local `_intake/
research-os-k12-literature*` root. That loader did not survive the
rebase: `main` had already landed its own two-batch mechanism
(`DEFAULT_CARDS_DIRS`/`load_default`, `hte/corpus/literature.py`) by
the time this branch rebased onto it, and the rebase kept `main`'s own
implementation over this branch's (commit `f720e7e8a`, "main's
implementation and tests stand"), so `discover_card_roots`/`load_local`
are not part of this PR and name nothing in this branch's own code.
`hte.cli`/`hte.runner` register `"literature"` against `load_default()`
instead, reading straight off `DEFAULT_CARDS_DIRS`'s two fixture
directories: both fixture batches combined, 12 cards, 36 evidence
items, no network, deterministic. The `literature` row below is
measured against that loader, the one this PR ships.

`literature`'s ground-truth count is 1: `load_default`'s 12-card,
36-evidence-item corpus (both fixture batches) carries exactly one
`GroundTruthEvent` (Bloom 1984's own mastery-learning meta-analysis).
K-fold holds that one event out in whichever of its 5 folds lands it,

interval; a coverage of `1.000` here is a full-marks read of a
single-event corpus. `quantum-history`/`education-atlas`'s own `>10`-
event rows carry the multi-event signal this doc's other rows lean on;
`literature`'s single event carries a narrower one. Measured directly:
`hte calibrate --diagnose --corpus literature` → `brier_score=
0.02262708642094153 over 1 of 1 held-out events (coverage_of_truth=
1.0)`, `DIAGNOSTICS.md`'s own reasons table all zero.

The full 25-country education-atlas sample's own after-fix number is not
in this table: one `run_calibration` call against it ran past 12 minutes
in this environment (the same call measured ~230s before this fix, in
the "Before" row above) and was stopped rather than left to keep running
past this write-up's own session. The 8-country subsample above is the
number `hte-synth realsweep`'s own default reproduces in about a minute;
`--education-atlas-full` reruns the slower full-sample call for a reader
who wants it. A larger candidate pool surviving `_candidate_key`'s own
finer dedup (fewer address collisions now merge two distinct candidates
into one) is the direct cost of the fix at this corpus's own scale:
`_matches_event` runs once per held-out event per surviving candidate,
so the full sample's own several-thousand evidence items pay for this
fix's own correctness in wall time neither `production` nor the
subsample, both far smaller, ever notice.

Every synth row above reads byte-identical before and after: `hte.synth`
items never carry an `OTHER`-filled slot (`make_world` always draws a
real concept id, never `other_id`, for a corroborating or noisy item) and
its own address space (thousands of combinations for 8 true events) makes
a same-address, different-interval collision between two distinct
planted events vanishingly unlikely, so none of the three fixes had
anything to change there. This is the expected, confirmed shape of a
fix scoped to real-corpus slot sparsity and coarse default binning, both
absent from a synthetic world by construction.

Three of four real corpora clear their own target; `production` does

### Why `production` stays at 0.250

`hte.diagnostics.coverage_report` puts every one of `production`'s six
uncovered claims under `slot_mismatch`, and the two covered ones are the
corpus's only pair of claims sharing a slot combination at all
(`prod-001-c0-e0`/`prod-005-c0-e0`, both `actor=student-researcher,
action=raised, object=tier-assignment, place=classroom-workspace`,
verified by hand against `hte.corpus.production.load(status_min=
"draft")`'s own 8 accepted claims and 16 evidence items). The other six
claims are each a distinct, deliberately unique test scenario (a
different actor/action/object combination demonstrating a different
part of the production schema); with no other claim on file sharing
even one resolved slot with any of them, no candidate-matching fix can
manufacture the corroboration a k-fold check needs. This is `hte.
calibrate.holdout_kfold`'s own documented tradeoff working as designed
on a small, low-redundancy fixture: coverage here comes only from
ANOTHER kept item sharing the held-out event's own exact slots, and this
local fixture ships one such pair among eight claims.

`hte.corpus.production`'s own design carries a real discovery lag
(`discovery_year` is a claim's own review-acceptance date, a separate
fact from its subject date) for exactly this reason: a live, larger
`load_supabase` pull would plausibly carry more claims, more
redundancy, and a real lag that picks discovery-date holdout instead of
k-fold. That path was not exercised
here (no Supabase credentials in this environment, and querying a live
production database was out of scope for a coverage-diagnostics change).
`production`'s own coverage ceiling is therefore read as a fixture-size
and redundancy limit, past the reach of this bead's own fixes.

## Ground truth

`bkt-hte-ground-truth-enrichment`, 2026-09-11. `production`'s own
coverage ceiling above ("a fixture-size and redundancy limit") and
`literature`'s own single ground-truth event were both structural, not
a candidate-matching bug: `production` carried one redundant claim pair
among eight accepted claims; `literature`'s adapter credited a finding
as ground truth on only one of the paper's own three ways a finding
gets attested (a meta-analysis, or a bare mention of the word
"replication" with no effect size behind it), never the third
(cross-card corroboration). This section reports what changed and the
numbers before and after, on this file's own `--diagnose`-fixed `hte
calibrate` (`choose_holdout_mode`'s auto mode selection, the "Before"/
"After" sections above), so no mode discrepancy needs separating out.

**What changed.** 22 new productions, `hte/data/production-fixtures/
prod-013.json` through `prod-034.json`: 4 cross-district replication
pairs (a pre-cutoff and a post-cutoff member sharing every concept
slot, from two different pseudonymous districts); 1 more replication
pair whose own review history dips back from "accepted" to "peer-
reviewed" and climbs to "accepted" again (revised-then-reaccepted); a
depth-3 citation chain (`prod-026` cites `prod-025` cites `prod-024`
cites `prod-023`, itself built from two more replication pairs on its
own two addresses, alongside the pre-existing depth-2 chain, `prod-011`
cites `prod-005` cites `prod-001`, untouched); 6 twins of pre-existing
ground-truth events; 2 more retracted productions. A fourth grade band
(`"3-5"`) and a third pseudonymous district (`"district-c"`) both first
appear in this batch; no new slot value, so `hte/data/vocab-production-
seed.json` is unchanged. `hte.corpus.literature._is_ground_truth` now
also requires a quantified effect size (`_has_effect_size`) behind a
bare `"replicat"` mention, and a new function, `_corroborated_dois`,
adds the paper's own third way: two or more cards naming the same
`(mechanism, object)` reading, from at least two distinct first
authors, become ground truth together. 5 real cards, copied verbatim
from the local `_intake/research-os-k12-literature/` tree, land in
`hte/data/literature-fixtures-batch-two/educational-methods/`: Deci,
Koestner, and Ryan 1999 (a meta-analysis on its own); Deci and Ryan
2000 and Oudeyer, Kaplan, and Hafner 2007 (corroborating Deci,
Koestner, and Ryan 1999's own `self-determination`/`motivation`
reading); Alonzo and Steedle 2009 alongside Corcoran, Mosher, and Rogat
2009 (an independent corroborating pair on a `learning-gain` reading,
no shared author with the first group or with each other's own group).
