# Bucket can ground model-assisted learning plans

Bucket has the graph and review boundaries needed to evaluate DeepSeek and Laya against the learning-slope idea. **Use DeepSeek to propose evidence-backed prerequisites and explain accepted plans; evaluate Laya for bounded classification.** Keep access decisions, graph acceptance and mastery in application code. The existing frontier algorithm needs changes before it can represent minimum remaining learning. Neither model has been tested against Bucket, and source inspection establishes neither deployment health nor model quality. This assessment covers source at `ce7f93952d353ed3127625470c4155fd17ed2ab3` and public model documentation reviewed on September 25, 2026.

## Learning slope and prerequisite closure

The current algorithm follows incoming prerequisites until it reaches roots or learner stage `understanding` and above. It accumulates negative log confidence and uses hop count as a tie-break; **it has no study-time cost**. Its descending-hop output does not guarantee prerequisite order when alternate routes exist. The gap excludes frontier nodes, including unmastered roots. Access filtering can also leave a node with no visible prerequisites, making it appear foundational. ([Frontier algorithm](/home/gian/agfarms/bucket-foundation/src/lib/research-os/frontier.ts:76))

The proposed learning layer should traverse backward from a target to accepted foundations or assessment-supported mastery, retain every mandatory branch, deduplicate shared concepts and produce a topological study order. Mark inaccessible or missing prerequisites as incomplete coverage without exposing protected content. Include unmastered foundations in remaining work. Pedagogical foundations are the working interpretation of “earliest knowledge,” pending user confirmation; historical chronology needs separate relations.

Define learning slope as estimated effort and prerequisite readiness per concept, with uncertainty attached to effort. An initial planner can sum remaining effort over the required closure. Alternative prerequisites need explicit AND/OR semantics before cost minimization has a stable meaning. Learner-specific estimates need observed study and assessment data. A proposed effort estimate remains a hypothesis until that evidence supports it; the first release should claim a valid plan under stated assumptions, with no claim of optimal learning.

## Model roles

DeepSeek V4.1-Flash is a text-and-image MoE with a one-million-token context and MIT-licensed weights. Its publisher describes a 552B backbone plus 196B Engram parameters; active parameters do not describe total deployment memory. The release lacks a Jinja chat template. ([Model card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)) Reference inference uses eight tensor-parallel ranks and checkpoint conversion, which leaves Bucket hardware feasibility untested. ([Inference guide](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/inference/README.md))

**Hosted DeepSeek is the first evaluation candidate.** The documented `deepseek-flash` alias points to V4.1-Flash and supports OpenAI-format requests. Published cache-miss input prices are $0.15 off-peak or $0.30 peak per million tokens; output is $0.60 or $1.20. Record returned model identity because aliases can change. ([API pricing](https://api-docs.deepseek.com/quick_start/pricing/)) Evaluate evidence extraction, prerequisite explanations and grounded tutoring against Bucket fixtures. Context capacity does not establish source fidelity or pedagogical correctness.

Laya offers a different seam: short-context decisions over finite labels. The English root model has 421M parameters and a 512-token default budget under Apache-2.0. Its publisher warns about option-label bias and unusable `action.act_probability`. ([Model card](https://huggingface.co/convaiinnovations/laya)) Structured projection supports enums, booleans and bounded integers, while excluding free strings, arrays and nested objects. ([Schema API](https://nandhakishorm.github.io/laya/structured/)) This supports request routing or review flags. Generation and evidence quotation require another component.

Laya needs a task-specific evaluation before adoption. Publisher typed-decision accuracy is about 0.36 for the root checkpoint against a 0.461 majority baseline, rising to 0.766 after task fine-tuning. Labels include teacher distributions; these results do not establish independent correctness or Bucket performance. ([Benchmark report](https://github.com/NandhaKishorM/laya/blob/main/BENCHMARKS.md)) Long-input aggregation chooses maximum or most-confident windows, so its confidence lacks document-level calibration. ([Agent API](https://nandhakishorm.github.io/laya/reference/agent/)) Keep classification probabilities separate from graph confidence and learner mastery.

## Bounded pilot

Start with one subject area, reviewed prerequisite pairs and atom-grounded tutor cases. Use source-disjoint and document-disjoint training, calibration and test splits; fix thresholds before the final test. Use nonpersonal public or synthetic inputs whose terms permit processing by the chosen hosted provider. Keep private learner records outside this pilot. DeepSeek should emit proposals with source spans; reviewers retain acceptance authority. Laya should log shadow decisions over a small relation-label set, with abstention for uncertain cases. Neither pilot should update learner mastery or graph edges without existing authorization.

The TypeScript client accepts an OpenAI-compatible endpoint but lacks per-role routing and a structured-output parameter. Add explicit role configuration and validate every response in Bucket. ([Client](/home/gian/agfarms/bucket-foundation/src/lib/llm/client.ts:30)) Candidate generation currently supplies titles and summaries; add source spans for reviewable evidence. ([Candidates](/home/gian/agfarms/bucket-foundation/src/lib/research-os/inference/propose.ts:61)) Extend the adapter to retain returned model identity, finish reason and cache usage. Replace unknown-model Sonnet pricing fallback with provider-aware usage accounting. ([Pricing code](/home/gian/agfarms/bucket-foundation/src/lib/research-os/llm.ts:36))

Proposed release gates are zero access-control violations and zero accepted cycles across the evaluation set; every accepted edge must have a verified supporting source span. Compare prerequisite precision with existing lexical proposals and tutor grounding with the current provider before promotion. Fix token, request, latency and spending ceilings before endpoint testing, with a kill switch. Require Laya to beat both the majority baseline and a simple rules baseline on held-out data at an agreed abstention coverage. Stop adoption if it fails those comparisons. Stop the learning-plan release if hidden prerequisites appear satisfied or any required unmastered foundation disappears.

Provider contract tests must cover malformed output, timeouts, usage fields and model identity. Fixtures must cover an all-required diamond with unmastered roots, a shortcut and cycle, hidden prerequisite coverage, and out-of-domain classifier abstention. Check mastery evidence in each learning-plan fixture. Existing test files provide starting points; this research ran no inference or runtime tests. The next decision is whether the measured benefit justifies maintaining each adapter. DeepSeek and Laya can enter through separate pilot gates while the learning graph advances through its own correctness checks.
